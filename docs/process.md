# 项目流程文档

本文档定义 `keyword-translator` 的里程碑流转、角色职责、测试与验收规则。除非用户明确调整，否则后续协作都按这里执行。

## 里程碑

- `M0 立项与规范`
  - 明确目标用户、范围边界、技术选型和协作方式。
- `M1 项目骨架`
  - 完成浏览器扩展基础结构、构建流程、共享类型和最小可运行入口。
- `M2 核心注释能力`
  - 完成词库匹配、页面注释、开关控制和基础排除规则。
- `M3 词库管理`
  - 完成词条增删改查、设置页管理和存储持久化。
- `M4 稳定性与兼容性`
  - 完成动态页面支持、错误处理和常见文档站点兼容性修正。
- `M5 测试与发布准备`
  - 完成单元测试、E2E 测试、文档整理和发布前验收。

## 角色职责

### 项目经理

- 维护里程碑状态、风险和验收节奏。
- 汇总开发与测试结果并向用户阶段汇报。
- 在用户未批准前，禁止推动最终分支提交、推送或发布。

### 架构师

- 维护架构文档、模块边界和工程规范。
- 明确数据模型、消息流转和测试策略。

### 前端工程师

- 负责扩展代码实现、UI 和内容脚本行为。
- 保证代码风格统一并补充必要文档。

### 测试工程师

- 维护测试计划、单元测试和 E2E 测试。
- 提交测试完成度报告，标明通过项、失败项和残余风险。

### 用户

- 对里程碑结果做最终业务确认。
- 明确批准后，项目才允许提交目标分支或继续对外发布动作。

## 项目经理验收标准

- 里程碑目标和交付物一致。
- 测试工程师已提交测试完成度报告。
- 阻塞问题已关闭，或已经明确列出处理计划。
- 相关文档、实现和说明保持一致。
- 用户需要知晓的风险已清楚记录。

项目经理验收结论分为三种：

- `通过`
- `有条件通过`
- `不通过`

## 用户批准规则

- 未获得用户明确批准前，不得执行最终分支提交、推送、合并或发布。
- 用户批准必须是清晰的文字确认，不以默认同意代替。
- 即使测试通过，如果出现新的阻塞风险，也要暂停提交并重新走验收流程。
- 里程碑汇报必须先给出完成情况、测试结果、残余风险，再请求用户批准。

## 推荐流转顺序

1. 架构师明确本阶段边界和规范。
2. 前端工程师完成实现。
3. 测试工程师提交测试完成度报告。
4. 项目经理做验收并向用户汇报。
5. 用户明确批准后，再执行分支提交或推送。
